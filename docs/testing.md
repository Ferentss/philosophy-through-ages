## Не вдалося перевірити

- `npm install` для CMS завершується `EAI_AGAIN`, оскільки npm registry недоступний. Тому повний CMS lock-файл потрібно відновити на комп’ютері користувача, після цього перевірити `npm ci`. Production-збірки frontend/CMS тут не перевірені.
- CMS `npm run typecheck` і генерацію `payload-types.ts`: потребують npm-пакетів.
- Схему PostgreSQL, застосування двох міграцій, seed та збереження даних: немає робочої тестової бази.
- Живі `GET /api/common`, `GET /api/page`, адмінпанель, створення/редагування записів. Локальні API-тести викликали handler із *mock* Payload і перевірили лише його логіку, а не реальний сервер.
- E2E через браузер, включно з Loading/Error/Success, адаптивністю, редагуванням медіа.
- Публікацію на Vercel, Blob storage й CORS між реальними доменами: немає облікових даних.

## Завершальна перевірка у VS Code

Після `npm run setup` CMS-скрипт оновить `cms/package-lock.json` через `npm install`; цей оновлений файл потрібно закомітити та перевірити за допомогою `npm ci`.

```powershell
npm run setup
npm run typecheck:site
npm --prefix cms run generate:types
npm run typecheck:cms
npm run build:site
npm run build:cms
npm run test
npm run dev
```

Після запуску CMS в іншому терміналі: `npm run seed`. Відкрийте `/admin` на порту 3000, змініть опис філософа, оновіть сайт на порту 5173 і переконайтесь, що зміна збереглася після перезапуску. Окремо перевірте HTTP 400 та 404, кнопку повтору після вимкнення CMS, меню на мобільному екрані та upload Media.

**Перед production**: згенеруйте правильний snapshot і перевірте міграції на *одноразовій тестовій* Neon БД. Не виконуйте неперевірену ручну міграцію на важливій базі.

## Додаткові перевірки української версії

- `npm test`: запускає 16 початкових Node.js тестів, 4 тести фронтенду та 4 нові перевірки TypeScript/скриптів.
- `git log --oneline -9`: усі повідомлення українською; у ZIP присутня папка `.git`.
- Спроба `npm ci --offline` у `frontend/` без інтернету не завершилася: відсутній кеш пакета `typescript@5.7.3` (`ENOTCACHED`). Це обмеження середовища, а не результат перевірки реальної збірки.

## Перевірка появи публічного сайту (після налаштування Neon)

1. Перевірте, що `http://localhost:3000/admin` відкриває адміністративну панель.
2. Заповніть базу **один раз** за допомогою `npm run seed` у другому терміналі.
3. Запустіть `npm run check:site`. У відповіді мають бути 7 секцій, 5 епох, 6 філософів і 6 переказів ідей.
4. Відкрийте **http://localhost:5173/**, перевірте всі секції та перемикання цитат.
5. Змініть в Payload опис філософа й оновіть публічний сайт. Зміна має з'явитися без перезбирання Vite.
6. Якщо `check:site` повертає `500`, знайдіть першу помилку у терміналі CMS. Один лише текст `HTTP 500` не визначає причину.

Зміни в новій версії перевірялися локальними Node.js тестами. Повноцінний запит до приватної Neon-бази користувача в середовищі підготовки недоступний.

## Режим перегляду оформлення без CMS

Для огляду макета використовуйте `http://localhost:5173/?preview=1` у режимі Vite dev. Демо має явне повідомлення, що це **не** реальні дані з бази. На звичайній адресі `http://localhost:5173` дані читаються через `/api/common` та `/api/page?path=/`; якщо головна сторінка не існує, dev-сайт може показати це саме позначене демо, щоб не залишати порожній екран. Після `npm run seed` звичайна адреса показує дані CMS. Це не замінює інтеграційної перевірки приватної Neon-бази користувача.
