# Виправлення `Failed to fetch` у локальній мережі

У старій версії браузер звертався до `http://localhost:3000`.
Коли сторінку відкрито через IP іншого комп'ютера, `localhost` означає
саме комп'ютер відвідувача, а не сервер із Payload CMS.

## Що змінено

1. `frontend/vite.config.ts` — проксі `/api` на `127.0.0.1:3000`.
2. `frontend/src/api/client.ts` — відносні запити до `/api` у development.
3. `cms/src/endpoints.ts` і `frontend/src/lib/dom.ts` — локальні медіафайли через проксі.
4. `frontend/.env.example` — більше не пропонує `localhost` для клієнтського API.

## Перевірка

1. У `cms/.env` встановіть `PAYLOAD_SECRET` і `DATABASE_URL`.
2. Запустіть `npm run dev`.
3. На комп'ютері розробника відкрийте `http://localhost:3000/admin`.
4. Відкрийте `http://localhost:5173/api/common`: очікується JSON.
5. З іншого пристрою відкрийте `http://IP-КОМП'ЮТЕРА:5173/api/common`:
   очікується та сама JSON-відповідь.
6. Перевірте `http://IP-КОМП'ЮТЕРА:5173/`.

**Важливо:** Vite-проксі не створює базу даних та не виправляє відсутні
секрети CMS. Реальний тест Neon/адмінпанелі потрібен окремо.
Використовуйте локальну мережу, а не відкритий інтернет.
